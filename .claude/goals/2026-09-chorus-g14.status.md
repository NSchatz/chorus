## Decisions taken

- D1 (2026-10-02): the interactive shell's `grep` and `find` are unreliable here (§0.11); the goal
  uses `command grep` and `rg`.
- D2 (2026-10-02): tracks follow goal 13's shape: research and a survey first, a design envelope
  (`/cache/tmp/chorus-g14/design.md`, the coordinator's), then build tracks in worktrees, each a
  branch and a PR gated and merged one at a time under `goals-heavy` then `chorus-heavy`. Every
  track touches firmware, so each PR runs the full `make gate`, not only `make tier-fast`.

- D3 (2026-10-02): image bytes travel inside the endpoint's own encrypted session (new types
  `0x18`-`0x1A`), not over HTTP: the control plane caps requests at 16 KiB, has no file route and a
  fixed thread population, and the session is already authenticated by the pinned keys (K62), so
  the image needs no second trust path; integrity is a SHA-256 in the offer. No signing key is
  created (creating keys is not an agent's act). Reasoning: `design.md` sections 2-3 and the
  ota-core ADR.
- D4 (2026-10-02): §0.7's "an OTA push to a real address refuses unless `CHORUS_OWNER_AT_BENCH` is
  1" is taken literally: the server refuses a transfer to a non-loopback peer unless its own
  environment carries it, read in the approved Rust form; tests and QEMU use loopback only. How
  the owner's deploy sets it lives under `docs/` alone.
- D5 (2026-10-02): the endpoint id is random per board (`chorus-` + 12 hex), kept in NVS, never
  the MAC (K27).
- D6 (2026-10-02): wave 1 runs four tracks in parallel (`ota-core`, the foundation line;
  `adoption-server`; `identity-discovery`; `provisioning`), wave 2 `ota-server` and `ota-qemu`
  after the first two merge, because the server's sender and the QEMU run build on the wire.

- D7 (2026-10-02): the QEMU libraries come from conda-forge under `/cache/opt/` as §0.11 and
  §0.2 say for this goal; the planning research's "gray zone" note is settled by the brief.
- D8 (2026-10-02): `ota-qemu` is two PRs: the emulator profile and an adopted boot now (it needs
  only the merged identity and store), the OTA run after `ota-core` and `ota-server` merge.
