## Decisions taken

- D1 (2026-10-03): the interactive shell's `grep` and `find` are unreliable here (§0.11); the goal
  uses `command grep` and `rg`.
- D2 (2026-10-03): line C's wording ("MQTT discovery") is read through P10 as approved: the opt-in
  read-only publisher of Option M2, with no Home Assistant discovery topics. Reasoning: the
  approval line in `CHECKPOINT-K.approved` and P10's "Goal 15 line C: testable as written" row.

- D3 (2026-10-03): the exporter is a route on the existing control listener, not a new port or
  thread; the metric names are fixed in the design before the build so the homelab rules and
  dashboards are written against them in parallel. Reasoning: `design.md` section 1.
- D4 (2026-10-03): the exporter track's merge gate is the full `make gate` (it changes the wire
  and the firmware); `ctl` and `mqtt` merge on `make tier-fast` (§0.3).
- D5 (2026-10-03): homelab has no Alertmanager; §19's "routed through homelab's HA-webhook
  channel" is met by the `severity` label homelab's Grafana forwarder routes on, and no alerting
  file is edited. No "chorus down" rule: homelab's `ScrapeTargetDown` covers it.

- D6 (2026-10-03): the homelab scrape target is the proxy-bridge gateway literal that homelab's
  own open PR #237 already uses for the same service (Prometheus expands no variables there and a
  host-network server has no container name); it is a container-bridge address, not a LAN one, it
  stays in homelab's file only, and the PR body and commit write a placeholder. Reasoning: the
  track's note `/cache/tmp/chorus-g15/track-homelab.md`.

- D7 (2026-10-03): "corrections" is exported as the rate-correction gauge
  (`chorus_speaker_rate_correction_ratio`; BRIEF 5.9 calls it the correction rate); nothing counts
  discrete corrections. Reasoning: ADR 0115.
- D8 (2026-10-03): chorusctl has a fifth exit code, 4 not-found (ADR 0114); the publisher has
  `--mqtt-keepalive-s` beyond the envelope (ADR 0116); the MQTT codec is its own crate `crates/mqtt`.
- D9 (2026-10-03): the exporter PR merged on a fourth gate run whose only failure was the known
  goal-13 `tv_low_latency` timing flake (re-run green), after a full PASS in round 3 on the tree
  before #116 was merged in. The coordinator's brief to the track allowed one re-run of the known
  flakes; the final `make tier-full` on main (C.3) is the plain PASS the merge rule asks for.
