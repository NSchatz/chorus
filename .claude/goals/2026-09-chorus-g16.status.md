## Inputs that bind this goal

- P9 as settled (`CHECKPOINT-K.approved`): "Option A: Symphonia 0.6.1 under an MPL-2.0 ADR,
  libopus, dr_flac; AAC off". The settled formats are MP3, FLAC, Vorbis, Opus, ALAC and WAV; AAC is
  not compiled, an AAC or HLS-with-AAC URL fails with a clear error, and the UPnP Sink list omits
  `audio/mp4` AAC and `audio/aac`. Decoding runs in chorus-server; endpoints get PCM, FLAC or Opus.
- ADR 0044 (goal 6): libopus 1.6.1 is vendored under `third_party/opus` (decoder units, fixed
  point) and built by `crates/opus-sys`; Symphonia's FLAC crates are already excepted in `deny.toml`.
- P6 as settled: "Option B: UPnP AV renderer in Rust inside chorus-server plus OpenHome services";
  the UPnP AV renderer (choice U1, written from the specs) is this goal's, OpenHome is goal 17's.
  Two security rules come with U1: GENA delivery URLs only inside a configured subnet list
  (CallStranger), and `SetAVTransportURI` fetches only `http`/`https` with the §4.8 bounds.
- K57, K59: a renderer per room, saved group and live group; stable identities (UUIDv5 per target;
  a live group's key is its sorted member rooms); K78 "take the room" when a group is cast to.
- K60, §0.9: clean-room; gmrender-resurrect, upmpdcli, MPD (GPL) are never opened.
- §0.11: "goal 16 keeps `make image` green when libopus (C) arrives".
- Naming: "UPnP AV media renderer", never "DLNA Certified".

## Decisions taken

- D1 (2026-10-03): the interactive shell's `grep` and `find` are unreliable here (§0.11); the goal
  uses `command grep` and `rg`.
- D2 (2026-10-03): the server's wire encoders (FLAC, Opus towards endpoints) are not in §20's
  scope and are not built here; the server keeps sending PCM. ADR 0044's aside that "the server's
  Opus encoder is goal 16's" is read against §20, which lists decoders, HTTP streams, the image
  and the renderers only. Listed under follow-ups.

- D3 (2026-10-03): HTTPS is in this goal: rustls 0.23.45 with the ring provider and the image's
  own CA bundle (no webpki-roots, no aws-lc-rs). Stored alarm URLs and most radio streams are
  https, so an http-only reader would not serve §20 item 1. Reasoning: `decoders.md` section 5;
  the fetch track's ADR carries it.
- D4 (2026-10-03): HLS is built to its smallest correct scope with AAC off: playlists and packed
  MP3 segments; AAC, MPEG-2 TS, fMP4, encrypted and byte-range playlists are refused by name
  (P9: "an AAC or HLS alarm URL fails with a clear error"). Reasoning: `decoders.md` section 4.
- D5 (2026-10-03): the image keeps its static musl PIE on the distroless static base; the C
  (libopus, ring) is compiled by the already pinned zig 0.16.0 as the musl C compiler, with
  rustc's own link. Reasoning: `image.md`; the decode track's ADR carries it (§20 item 2 "by ADR").
- D6 (2026-10-03): the control model gains a `player:<id>` source and a non-persisted now-playing
  record emitted on the room objects, so the MQTT gap goal 15 noted closes with no MQTT change.
  The renderer's `audio/mp4` Sink entry stays (ALAC lives there); AAC inside it is refused at
  play time. Reasoning: `design.md`; the tracks' ADRs carry them.
- D7 (2026-10-03): the tracks open PRs and the coordinator merges them in order (the pure UPnP
  core, fetch, decode + image, the plumbing, then the renderer), re-running `make tier-fast` on
  each branch after merging main, since chorus's heavy lock runs one gate at a time.
