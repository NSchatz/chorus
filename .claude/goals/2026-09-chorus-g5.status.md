## Decisions taken

- 2026-09-30: v2 lives beside v1 as `chorus_protocol::v2`; v1's three messages are carried into
  v2 byte for byte, so their v1 vectors are their v2 vectors, and the C endpoint keeps v1 until
  goal 6. `fixtures/protocol/v2` joins the shared-fixtures check with its C reader pending (goal
  6). Reasoning: the framing ADR (end-to-end PR) and `docs/conventions.md` rule 9.
- 2026-09-30: key exchange Noise_XX_25519_ChaChaPoly_SHA256 over vendored RustCrypto primitives
  (first external crates; K95 by record), not TLS-PSK (a PSK cannot exist before first contact;
  Mbed TLS has no raw public keys). ADR 0039. unicode-ident's Unicode-3.0 allowed for that crate
  only by the same ADR.
- 2026-09-30: one ADR per PR is enforced (number = PR number), so the three records ride three PRs:
  key exchange (#39), framing (the end-to-end PR), codec negotiation (a third PR).
- 2026-09-30: "never create keys" (K4) is read as credentials for services; the software
  generating a device's own key at runtime, and public test keys in fixtures, are product
  behaviour and test data. No agent-created key is stored anywhere.
- 2026-09-30: the handshake runs in the server's slot reader thread, not the acceptor, so a slow
  peer cannot stall accepts (build agent, branch `chorus-g5/v2-end-to-end`).

- 2026-09-30: the Linux client binary needs libasound, absent here; alsa-lib 1.2.16.1 was
  installed rootless from conda-forge into `/cache/opt/chorus-alsa` (micromamba), and
  `make verify-null-device` ran both real binaries over a v2 session (adopted, 2993 chunks played
  on ALSA `null`). The gate's end-to-end test uses the real server binary and the client's real
  session and playout path with a modelled device (the client forbids a fake-sink flag). Goal 7
  owns putting an ALSA `null` run in the gate.
- 2026-09-30: the host-built C endpoint speaks v1 until goal 6, so firmware's session-outage check
  pairs it with the v0.1.0 server built from its tag (`tools/lib.sh v1_server`); goal 6 returns it
  to the server at HEAD. The bench scripts that pair real ESP32 boards with the server
  (`tools/endpoint-rig-run.sh`, `tools/wireless-characterization-run.sh`) need goal 6's firmware
  first; no bench session is scheduled before then.
- 2026-09-30: a stream now starts when a session is up and negotiated, not when a socket is
  accepted; a serve-once server now waits (up to 2 s) for its writers to deliver `stream_end`
  before exiting (a pre-existing race the new test exposed).
- 2026-09-30: no minor release: the endpoint firmware still speaks v1, so a release now would ship
  a server its own firmware image cannot join; goal 6 is the natural point.
- 2026-09-30: follow-ups: the control plane has no `key_changes` list yet (the server's log and
  its pin store surface a key change; the app and HA surface it in goals 14, 18, 21); the key and
  pin file helpers are duplicated in the server and client crates.
