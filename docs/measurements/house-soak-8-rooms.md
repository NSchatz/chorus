**HOST SOFTWARE SOAK ON ALSA NULL, NOT A HARDWARE MEASUREMENT AND NOT TIMING EVIDENCE** (BRIEF.md section 3.1 rule 3). Every process ran on one development host over loopback; every endpoint played into ALSA's `null` device, which accepts every frame at once and reports a delay of zero, so nothing here says when a sample would have reached a DAC, and no sync bound is graded. What it grades is that a whole house keeps working under a steady command load for as long as it ran: threads, memory, fanout, limits and sessions. The three-day hardware soak (AC-4, `tools/soak-run.sh`) is a different run on real endpoints and is not this.

## What ran

- One `chorus-server` (debug build): `--slots 8 --control-listen --serve-forever --source tone --max-clients 16 --control-workers 8 --civil-time mon-23:30 --ephemeral-identity`, the repository's stream contract from `config/verification.conf`, and `--allow-non-realtime --allow-unlocked-memory` (this host grants no real-time priority and less locked memory than the server wants, so it says so in every status line).
- Eight rooms (ASSUMED names, the house of `docs/measurements/sim-house-8-rooms.md`; the owner's room list is an open Needs item): living, kitchen, dining, primary, office, patio, bathroom, guest; `bathroom` declared wireless (`--zone bathroom=wireless`).
- 10 `chorus-client` endpoints on ALSA `null` (the client has no fake sink by design), each with `--rejoin`, its own delay log and `--ephemeral-identity`: bathroom (bathroom), dining (dining), guest (guest), kitchen-l (kitchen), kitchen-r (kitchen), living-l (living), living-r (living), office (office), patio (patio), primary (primary). living and kitchen each hold two, attached `link: wired` and bonded FL/FR before they played; `bathroom`'s endpoint runs `--transport wireless`.
- libasound: `/cache/opt/chorus-alsa/lib`.
- One event-stream subscriber for the whole run, and the seeded command load (`tools/house-soak/load.py`): seed 20261001, one command every 2000 ms for 3600 s, each built from the state the last answer carried. Commands the server does not know would be counted as unknown and the load would carry on.
- RSS and thread counts of every process off `/proc/<pid>/status` every 10 s (ASSUMED period).

- Any timing: inter-device error, latency, the audio thread's tick against its deadline (the server does not count tick overruns yet; ADR 0077 leaves measuring the tick at S = 32 as a follow-up). ALSA `null` reports no delay.

- Real endpoints, a real network, Wi-Fi, the C endpoint.
