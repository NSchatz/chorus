# fixtures

Committed test data. Nothing in here is generated by a test run, and no test
writes to this directory. That is the point: these files are the contract that
two independent implementations of the same protocol are held to, so they have
to be reviewable in a diff and stable across languages.

## `protocol/`

One golden vector per message type in the catalog, as a pair of files:

- `<name>.hex` is the frame, byte for byte, including its 3-byte frame header.
  Whitespace separated hex, `#` starts a comment. Hex rather than raw binary so
  that a change to a vector shows up as a readable diff and every byte can
  carry a comment saying which field it belongs to.
- `<name>.fields` is the canonical input those bytes encode: one
  `key = value` per line, `#` starts a comment, byte strings are unseparated
  hex.

The round trip both directions is asserted in
`crates/protocol/tests/golden_vectors.rs`:

1. parse `<name>.fields`, encode it, and require the bytes to equal `<name>.hex`
2. decode `<name>.hex` and require the recovered fields to equal `<name>.fields`

A second-language implementation (the ESP32-S3 C components in the embedded
phase) is expected to run the same two assertions against the same files. That
is what keeps the two implementations from drifting apart, and it is why the
format deliberately needs nothing more than a hex parser and a `key = value`
splitter to read.

The field layout each of these follows is `docs/protocol.md`.

## `sync/`

One simulator scenario per file, `*.cfg`, in the same `key = value` format.
Each carries the whole configuration (seed, run length, clock skews, network
delay and jitter) plus the two assertions that scenario is committed to hold:
how quickly the modelled playout error has to come inside the bound, and what
the bound is.

`crates/sync/tests/simulator_regression.rs` runs every file in this directory,
so adding a scenario is adding a file. There is nothing to register.
